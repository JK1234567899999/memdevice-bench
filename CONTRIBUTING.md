# Contributing

MemDeviceBench welcomes code, documentation, metric definitions, instrument importers, dataset cards, public benchmark traces, and new experiment-profile schemas.

## Contribution quality

A pull request must make a technically meaningful and independently reviewable change. Duplicate, artificial, autogenerated-only, or contributor-count-gaming pull requests will be closed. The goal is a useful scientific commons, not a vanity metric.

## Setup

```bash
git clone https://github.com/JK1234567899999/memdevice-bench.git
cd memdevice-bench
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
make check
```

## Good first contributions

- Add an importer that maps a real instrument export to the canonical schema.
- Add a compact, redistributable trace with a metadata sidecar, dataset card, and license.
- Add a metric with its equation, assumptions, units, failure behavior, reference, and tests.
- Add validation for a common terminal-definition or instrumentation failure mode.
- Add a device/profile example that clarifies 2T, 3T, 4T, `1T1R`, or `1T1C` semantics.

## Scientific requirements for tags

- Place each label on the correct axis: technology, platform, mechanism, material, behavior, or experiment.
- Do not add `TFT` as a synonym for a memory technology.
- Do not infer a switching mechanism from the technology name alone.
- Use `unknown`, `mixed`, or notes when evidence is incomplete.
- `terminal_count` must describe the accessible measured DUT and be consistent with terminal platform tags.

## Scientific requirements for metrics

Every new metric must document:

1. exact mathematical definition;
2. preprocessing and normalization;
3. valid data range and units;
4. failure behavior;
5. whether higher or lower is preferable, when meaningful;
6. sensitivity to read noise, timing, pulse conditions, and state range;
7. at least one test using a trace with a known expected result;
8. a literature reference when the metric is not original.

## Energy-specific requirement

A contribution must not estimate multi-terminal programming energy from channel read conductance. Use measured programming-path current or report energy as unavailable. Waveform integration should document bandwidth, trigger alignment, probe loading, and integration window.

## Dataset requirements

Do not upload confidential, embargoed, proprietary, export-controlled, or personally identifying data. Confirm that the dataset license permits redistribution. Include a dataset card using `datasets/TEMPLATE.md`, a metadata sidecar, and checksums for externally hosted data.

## Pull request process

- Open an issue before a large change.
- Keep each pull request focused.
- Add tests and documentation.
- Run `pytest`, `ruff check .`, and `mypy src/memdevice_bench`.
- A maintainer other than the author should review scientific changes.

By submitting a software contribution, you agree that it is licensed under Apache-2.0. Dataset licenses must be stated separately.
